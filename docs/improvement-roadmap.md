# 개선 방향 로드맵

## 1. 즉시 개선

- 한글 인코딩 복구: README와 SDD 일부는 복구했지만 `shared/src/gameRules.ts`의 라벨 문자열과 나머지 문서 일부에 깨진 한글이 남아 있다.
- 테스트 추가: `getPartitionPlacement`, 제작 비용 검증, 룸 설정 sanitize, 게임 종료 조건을 우선 단위 테스트 대상으로 삼는다.
- PVP 정책 정리: 설정값은 존재하므로 실제 피해 규칙까지 구현하거나, MVP에서는 설정 UI와 타입에서 제외한다.
- 서버 파일 분리: `server/src/index.ts`를 room lifecycle, combat, spawning, crafting, objective, socket handlers로 나눈다.
- 입력 방어: `input`, 제작 요청, 아이템 사용 요청에 rate limit과 payload sanity check를 추가한다.

## 2. 플레이 경험 개선

- 온보딩 강화: 첫 플레이에서 제작 스테이션, 장비 강화, 물자 지키기 목표를 더 명확히 안내한다.
- 밸런스 도구화: 난이도, 웨이브, 좀비 체력/피해, 자원 드롭 가중치를 별도 설정 파일로 분리한다.
- 모드별 목표 피드백: 제한시간, 처치 목표, 물자 체력의 진행 상태를 더 강하게 시각화한다.
- 결과 공유 개선: 공유 이미지에 모드별 성과와 대표 아바타를 포함한다.
- 접근성 보완: 키보드 포커스, 버튼 레이블, 색 대비, 모바일 HUD 겹침을 점검한다.

## 3. 운영/상용화 준비

- 룸 만료 정책: 빈 방 삭제는 구현되어 있으나 비활성 로비, 장시간 플레이, 연결 끊김 복구 정책이 필요하다.
- 관측성: 서버 로그, 룸 생성/종료 이벤트, 에러 카운트, 평균 플레이 시간 지표를 수집한다.
- 배포 헬스체크: `/api/health`를 배포 플랫폼의 헬스체크와 연결하고 장애 알림 기준을 정한다.
- 저장소 전략: 결과 기록, 재접속 복구, 랭킹이 필요해지는 시점에 DB 스키마를 설계한다.
- 보안: CORS 허용 범위를 운영 도메인으로 제한하고 방 코드 무차별 대입 방지책을 둔다.

## 4. 제품 방향 후보

- 게스트 기반 파티 게임으로 유지: 짧은 세션, 공유, 이벤트 운영에 집중한다.
- 기록형 챌린지로 확장: 개인 베스트, 일간 랭킹, 모드별 업적을 추가한다.
- 오피스 브랜딩 강화: FURSYS 가구/공간을 맵 오브젝트와 제작 소재로 더 직접적으로 연결한다.
- 팀 모드 도입은 별도 의사결정으로 둔다. 현재 구조와 문구는 개인 경쟁 중심에 맞춰져 있다.
