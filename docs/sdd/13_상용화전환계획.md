# 13 상용화 전환 계획

## 1. 전환 원칙

- 게스트 플레이와 빠른 방 입장을 제품의 기본 진입 방식으로 유지한다.
- 회원가입, 결제, 관리자 기능은 MVP 핵심 루프 안정화 이후 별도 결정한다.
- 개인 생존 점수 경쟁을 기본 방향으로 유지하고, 팀 모드는 별도 제품 의사결정으로 둔다.
- 구현 범위를 늘리기 전에 안정성, 문구, 테스트, 운영 관측성을 먼저 보강한다.

## 2. 현재 MVP와 상용화 차이

| 영역 | 현재 상태 | 상용화 전환 필요 |
| --- | --- | --- |
| 세션 | 메모리 기반 룸 상태 | 룸 만료, 재접속, 장애 복구 정책 |
| 데이터 | 영구 저장 없음 | 결과 기록/랭킹 필요 시 DB 설계 |
| 보안 | CORS 전체 허용, 제한적 검증 | 운영 도메인 제한, 입력 검증, rate limit |
| 테스트 | 타입체크/빌드 중심 | 규칙 단위 테스트, 통합 테스트, 모바일 QA |
| 운영 | `/api/health` 제공 | 로그, 지표, 알림, 배포 헬스체크 |
| UX | 튜토리얼/설명 제공 | 첫 플레이 전환율 기반 온보딩 개선 |
| 문구 | 일부 한글 깨짐 | 전체 UTF-8 복구와 용어 일관화 |

## 3. 우선순위 로드맵

### 1단계: 안정화

- 한글 라벨과 문서 인코딩 복구
- 핵심 규칙 테스트 추가
- 서버 파일 모듈화
- PVP 설정의 유지/제거 의사결정
- 운영 환경 CORS와 입력 검증 강화

### 2단계: 운영 준비

- 룸 만료 정책과 비활성 방 정리 규칙 도입
- 서버 로그와 지표 수집
- 배포 플랫폼 헬스체크 연결
- 모바일/데스크톱 주요 해상도 QA 체크리스트 작성
- 결과 공유 이미지와 초대 링크의 운영 도메인 검증

### 3단계: 제품 확장

- 일간/주간 챌린지 또는 개인 베스트 기록
- 모드별 밸런스 지표 기반 튜닝
- FURSYS 오피스 브랜딩을 맵, 자원, 장비 이름에 더 명확히 반영
- 랭킹, 업적, 재방문 동기 기능 검토

## 4. 의사결정 필요 항목

- 영구 기록이 필요한가, 아니면 세션형 파티 게임으로 유지할 것인가
- PVP를 실제 기능으로 구현할 것인가, MVP에서 제거할 것인가
- 팀 모드를 도입할 것인가, 개인 경쟁 중심을 유지할 것인가
- 운영 계정/관리자 기능이 필요한가
- 사내 시스템 연동 또는 캠페인 전용 배포가 필요한가

## 5. 출시 전 체크리스트

- `npm run typecheck` 통과
- `npm run build` 통과
- 주요 브라우저에서 로비, 방 생성, 입장, Ready, 전투, 결과 공유 확인
- 모바일 터치 조이스틱과 HUD 겹침 확인
- `/api/health` 배포 환경 정상 응답 확인
- 한글 라벨 깨짐 없음
- 운영 도메인에서 Socket.IO 연결 정상 확인
