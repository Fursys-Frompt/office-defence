# 13 상용화 전환 계획

## 1. 확정 방향

- 상용 단계에서도 게스트 플레이를 유지한다.
- 외부 인증, 회원가입, 권한 연동은 우선 도입하지 않는다.
- 플레이어 식별은 세션 단위 닉네임과 서버가 발급한 임시 플레이어 ID를 기준으로 한다.
- 제품 정체성은 개인 생존과 점수 경쟁 중심으로 유지한다.
- PVP 설정은 유지한다.
- 좀비 처치 목표 모드는 방 전체 합산이 아니라 개인별 목표 선착순 경쟁으로 운영한다.

## 2. 게스트 플레이 원칙

- 첫 진입에서 로그인 요구 없이 바로 방 생성 또는 입장이 가능해야 한다.
- 닉네임과 아바타 선택은 진입 장벽을 낮추는 최소 프로필 입력으로 유지한다.
- 게스트 정보는 계정 자산처럼 취급하지 않는다.
- 장기 저장이 필요한 랭킹, 스킨 보유, 플레이 기록은 별도 결정 전까지 제품 범위에 포함하지 않는다.

## 3. 상용화 전 선행 정리

| 영역 | 작업 | 목적 |
| --- | --- | --- |
| 제품 문구 | 협동, 팀 역할, 역할군으로 읽히는 표현 제거 | 개인 경쟁 정체성 고정 |
| 서버 구조 | 룸, 전투, 스폰, 점수, 소켓 핸들러 분리 | 기능 확장과 테스트 용이성 확보 |
| 테스트 | 공유 규칙과 서버 상태 전환 자동 테스트 추가 | 밸런스 변경 안정성 확보 |
| 운영 | 서버 상태 확인, 에러 로깅, 비정상 입력 방어 추가 | 공개 서비스 안정성 확보 |
| UX | 첫 플레이 목표, 조작, 성장 피드백 강화 | 신규 사용자 이탈 감소 |

## 4. 게스트 기반 상용 기능 후보

### 우선 적용 가능

- 세션 내 개인 랭킹
- 방 코드 공유
- 아바타 스킨 선택 확장
- 맵과 모드 추가
- 개인 미션과 업적형 피드백
- 플레이 종료 후 공유 가능한 결과 카드
- 배포 상태 확인용 헬스 체크 API

### 별도 의사결정 필요

- 서버 재시작 후에도 유지되는 누적 랭킹
- 스킨 보유 상태 저장
- 시즌제 랭킹
- 결제 또는 광고
- 운영자 도구

위 항목은 DB 저장, 결제, 운영 권한, 배포 정책과 연결될 수 있으므로 구현 전 별도 확인이 필요하다.

## 5. 현재 MVP와의 차이

현재 MVP는 메모리 기반 룸과 스냅샷 중심 실시간 게임 루프를 제공한다. 상용 단계에서는 게임 루프 자체보다 운영 안정성과 반복 플레이 동기를 보강해야 한다.

상용화의 첫 단계는 기능을 크게 늘리는 것이 아니라, 현재 루프를 유지한 채 다음 기반을 정리하는 것이다.

- 문구와 모드명이 제품 방향과 일치해야 한다.
- 게임 규칙이 테스트 가능한 모듈로 분리되어야 한다.
- 비정상 입력과 방 폭주에 대한 방어가 있어야 한다.
- 모바일과 데스크톱에서 첫 플레이 성공률을 확인해야 한다.

## 6. 진행 중단 기준

다음 작업은 기존 범위를 넘어서는 의사결정이 필요하다.

- DB 스키마가 필요한 영구 저장
- 외부 인증 또는 소셜 로그인
- 결제, 광고, 스킨 판매
- 운영자 권한과 관리자 화면
- PVP 제거 또는 기본 흐름 변경
- 처치 목표 모드의 추가 승리 조건 변경
