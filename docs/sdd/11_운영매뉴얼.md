# 11 운영 매뉴얼

## 1. 로컬 실행

요구 사항: Node.js 20 이상

```bash
npm install
npm run dev
```

- 클라이언트: `http://localhost:5173`
- 서버/API/Socket: `http://localhost:3000`

## 2. 빌드와 실행

```bash
npm run typecheck
npm run build
npm start
```

`npm start`는 빌드 결과물 기준으로 Express 서버를 실행하고 정적 클라이언트 파일을 서빙한다.

## 3. 상태 확인

```bash
curl http://localhost:3000/api/health
curl http://localhost:3000/api/rooms
```

`/api/health`에서 확인할 항목:

- `ok`: 서버 응답 여부
- `rooms`: 메모리상 방 수
- `players`: 접속 플레이어 수
- `uptimeSec`: 프로세스 업타임

## 4. 배포 설정

- 실행 포트는 `PORT` 환경변수로 지정할 수 있다.
- Node.js 20 이상 런타임을 사용한다.
- 빌드 명령은 `npm run build`, 시작 명령은 `npm start`를 기준으로 한다.

## 5. 장애 대응

| 증상 | 확인 | 조치 |
| --- | --- | --- |
| 클라이언트 접속 불가 | 빌드 산출물과 서버 로그 확인 | `npm run build` 후 재시작 |
| 방 목록이 비어 있음 | `/api/rooms` 확인 | 정상일 수 있음. 접속자가 없으면 빈 배열 |
| Socket 연결 실패 | 브라우저 콘솔, 서버 포트, 프록시 설정 확인 | 운영 도메인의 WebSocket 설정 확인 |
| 한글 라벨 깨짐 | UI와 `shared/src/gameRules.ts` 확인 | UTF-8 문자열로 복구 |
| 진행 중 방 유실 | 서버 재시작 여부 확인 | 현재 구조에서는 복구 불가 |

## 6. 운영 주의 사항

- 방과 플레이어 상태는 메모리에 저장되므로 서버 재시작 시 모두 초기화된다.
- 운영 도메인에서는 CORS를 `*`로 두지 않는 것이 좋다.
- 공개 서비스 전에는 과도한 방 생성, 입력 스팸, 비정상 payload에 대한 방어가 필요하다.
- 현재 자동화 테스트가 부족하므로 밸런스 변경 전후에 수동 플레이 검증이 필요하다.
