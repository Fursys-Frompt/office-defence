# 06 화면 설계서

## 1. 입장 화면

### 구성 요소

- 프로젝트명
- 닉네임 입력
- 방 코드 입력
- 아바타 선택 그리드
- 아바타 대형 미리보기
- 방 생성/입장 버튼

### 설계 원칙

- 아바타 선택은 능력 선택처럼 보이면 안 된다.
- 아바타 설명에는 역할, 직업, 능력, 보너스 표현을 사용하지 않는다.
- 플레이어가 취향에 따라 고르는 스킨/외형 선택으로 보여야 한다.

## 2. 로비 화면

### 구성 요소

- 방 코드
- 플레이어 목록
- Ready 상태
- 방장 설정
- 시작 대기 상태

### 설계 원칙

- 로비는 팀 조합을 맞추는 화면이 아니다.
- 플레이어별 역할 안내를 표시하지 않는다.
- 방 설정은 세션 조건 조정에만 집중한다.

## 3. 게임 화면

### 구성 요소

- Canvas 플레이 영역
- 플레이어 HP/점수 HUD
- 자원 HUD
- 시간/웨이브/위협도 HUD
- 제작 재료/제작대 HUD
- 시설 설치 바
- 미니 랭킹

### 설계 원칙

- 플레이어가 지금 얻고 있는 개인 보상과 위험을 즉시 이해해야 한다.
- 협동 목표보다 개인 점수, 생존, 콤보, 성장 상태를 우선 노출한다.
- 맵 위 아바타는 작아도 취향 캐릭터로 식별되어야 하지만, 규칙상 우열이 있어 보이면 안 된다.

### 제작대 상호작용

- 컴퓨터 책상 제작대 근처에 접근하면 제작 가능 상태를 표시한다.
- 제작대 상호작용은 기존 이동/공격 흐름을 방해하지 않는 보조 UI로 제공한다.
- 제작대 UI에는 제작 가능한 무기, 필요한 재료, 현재 보유 재료, 장착 상태를 표시한다.
- 제작 불가능한 무기는 부족한 재료를 명확히 보여준다.
- 제작대 UI는 팀 역할이나 협동 임무처럼 보이면 안 된다.

### 무기 표시

- HUD에는 현재 장착 무기명을 표시한다.
- HUD에는 현재 장착 보조장비가 있으면 무기와 분리해 표시한다.
- 무기 장착은 기존 자동 공격 버튼을 대체하지 않는다.
- 무기별 공격 모션은 캔버스에서 짧고 명확하게 보여야 한다.
- 로봇청소기 드론은 플레이어를 따라다니는 보조 오브젝트로 표시한다.
- MZ의 키캡은 어그로 유도 범위와 소음 효과가 과도하게 화면을 가리지 않도록 표시한다.
- 연차 신청서 방패는 지속 시간을 알 수 있는 짧은 방어 링으로 표시한다.
- 경비아저씨의 손전등은 적과 배경을 과하게 가리지 않는 좁은 빛줄기로 표시한다.
- 모바일 화면에서는 제작대 UI가 조이스틱과 공격 버튼을 가리지 않아야 한다.

## 4. 결과 화면

### 구성 요소

- Result 제목
- 순위
- 닉네임
- 점수
- 킬 수
- 생존 시간
- 로비 복귀 버튼

### 설계 원칙

- 팀 승패가 아니라 개인 랭킹을 명확히 보여준다.
- 결과는 경쟁과 재도전을 유도해야 한다.

## 5. 디자인 문구 금지 사항

- 협동하세요
- 팀워크가 핵심입니다
- 역할을 선택하세요
- 지원/탱커/딜러 같은 직군 표현
- 조합 보너스
- 팀 승리

## 6. 권장 문구 방향

- 살아남고 더 높은 점수를 노리세요.
- 자원을 모아 장비를 강화하세요.
- 웨이브가 강해지기 전에 위치를 바꾸세요.
- 취향에 맞는 아바타를 선택하세요.
- 제작대에서 부품을 조합해 무기를 만드세요.
