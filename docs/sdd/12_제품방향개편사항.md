# 12 제품 방향 개편 사항

## 1. 개편 배경

기존 문서에는 협동 방어 생존, 역할별 개선, 직무형 캐릭터 방향이 섞여 있었다. 그러나 현재 제품 방향은 협동을 핵심 컨셉에서 제외하고, 캐릭터 구분도 역할군이 아니라 플레이어 취향을 만족시키는 장치로 재정의한다.

## 2. 확정된 방향

- 협동은 핵심 컨셉이 아니다.
- 여러 플레이어가 같은 방에 있을 수 있지만 목표는 개인 생존과 점수 경쟁이다.
- 캐릭터는 역할군이 아니다.
- 캐릭터는 능력치나 성장 방향에 영향을 주지 않는다.
- 아바타 선택은 취향, 개성, 화면 식별성을 위한 장치다.
- 문서와 UI 문구에서 팀워크, 역할 분담, 협동 보너스를 핵심 가치처럼 표현하지 않는다.

## 3. 폐기해야 할 이전 방향

- 협동 방어 생존 유지
- 역할별 개선 방향
- 직무별 캐릭터 역할
- 시설 업그레이드와 협동 보너스
- 러너/탱커가 팀 조합을 흔드는 방식의 설명
- 팀 단위 목표와 팀 승리 표현

## 4. 유지할 방향

- 사무실 생존 콘셉트
- 점점 강해지는 웨이브
- 자원 수집
- 자동 장비 성장
- 시설 설치
- 콤보와 점수 경쟁
- 짧은 세션형 플레이
- 결과 랭킹

## 5. 디자인 방향 영향

### 캐릭터

캐릭터 디자인은 역할을 설명하지 않고 취향을 만족시켜야 한다.

좋은 방향:
- 스타일 차이
- 분위기 차이
- 헤어/의상/색감 차이
- 수집하고 싶은 아바타
- 스크린샷에서 고르고 싶은 외형

나쁜 방향:
- 탱커처럼 보이는 캐릭터
- 힐러처럼 보이는 캐릭터
- 엔지니어처럼 보이는 캐릭터
- 역할별 장비가 과하게 드러나는 캐릭터
- 능력 차이가 있을 것처럼 보이는 설명

### 아이템

아이템은 플레이어 개인 성장과 생존 판단을 강화해야 한다. 특정 캐릭터 역할과 묶으면 안 된다.

### UI

UI는 개인 점수, 생존, 성장, 위험을 중심으로 구성한다.

## 6. 문서 정리 원칙

- SDD 전체에서 협동을 핵심 가치로 서술하지 않는다.
- 역할군이라는 표현은 사용하지 않는다.
- 아바타는 외형 선택으로만 설명한다.
- 멀티 구조는 세션 공유와 랭킹 경쟁 구조로 설명한다.
- 기존 구현과 충돌할 수 있는 부분은 구현 변경이 아니라 제품 방향 메모로 분리한다.

## 7. 후속 작업 후보

문서 방향을 실제 제품에 반영하려면 다음 구현 검토가 필요하다. 이 항목은 문서 변경 범위를 넘어서는 별도 의사결정 대상이다.

- 로비 문구에서 협동 뉘앙스 제거
- PVP 설정 유지 여부 검토
- 방 구조를 싱글 기본/멀티 선택으로 재정의할지 검토
- 아바타 이름을 역할 느낌이 없는 취향형 이름으로 변경
- 캐릭터 에셋을 능력 암시가 없는 스킨형 디자인으로 재작업
