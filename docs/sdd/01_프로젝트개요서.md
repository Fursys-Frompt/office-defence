# 01 프로젝트 개요서

## 1. 프로젝트명

Office Defence: Zombie Office Survival

## 2. 목적

FURSYS 오피스 공간을 모티브로 한 실시간 브라우저 생존 액션 MVP를 제공한다. 사용자는 별도 회원가입 없이 닉네임과 아바타를 선택해 방을 만들거나 기존 방에 입장하고, 좀비 웨이브 속에서 자원 수집, 제작, 전투, 시설 설치를 통해 개인 생존 점수를 겨룬다.

## 3. 제품 방향

- 협동 역할 분담보다 개인 생존 경쟁과 즉시 이해 가능한 액션을 우선한다.
- 아바타는 능력치가 없는 외형 선택 요소로 유지한다.
- 사무실 가구와 소모품을 자원, 무기, 시설, 보조장비의 소재로 재해석한다.
- 게스트 플레이, 방 코드, 초대 링크를 통해 진입 장벽을 낮춘다.
- 모바일 터치 조작과 데스크톱 키보드/마우스 조작을 모두 지원한다.

## 4. 현재 구현 범위

- 로비, 방 목록, 방 생성, 방 코드 입장, 초대 링크 딥링크
- 방 설정: 최대 인원, 게임 모드, 난이도, 제한 시간, 처치 목표, PVP 플래그
- 게임 모드: 제한시간 생존, 무제한 생존, 좀비 처치 목표, 물자 지키기
- Ready 상태와 카운트다운 후 게임 시작
- 서버 권위 20Hz 게임 루프와 Socket.IO snapshot 브로드캐스트
- 플레이어 이동, 자동 조준, 기본 공격, 자원 수집, 아이템 사용
- 제작 스테이션, 무기 제작/강화, 보조장비 제작/강화
- 파티션/책상 바리케이드/정비 거점 설치
- 주야간 사이클, 웨이브 전투/휴식, 난이도 튜닝
- 결과 랭킹, 결과 공유 텍스트/이미지, 외부 공유 링크
- 튜토리얼 및 게임 설명 모달
- 운영 확인용 `/api/health`, 방 목록용 `/api/rooms`

## 5. 제외 범위

- 회원가입, 로그인, 영구 계정
- DB 기반 영구 저장
- 결제, 광고, 인앱 구매
- 관리자 화면과 운영 권한 체계
- 팀 단위 승패 판정
- 직업/역할 기반 캐릭터 능력치
- 캐릭터별 고유 스킬 또는 밸런스 차이
- ERP/SSO 등 사내 시스템 연동

## 6. 성공 기준

- 신규 사용자가 로비에서 방 생성 또는 입장까지 막힘 없이 진행할 수 있다.
- 첫 플레이에서 이동, 공격, 수집, 제작, 생존 목표를 이해할 수 있다.
- 2명 이상이 같은 방에 접속해 동일한 전투 상태를 볼 수 있다.
- 게임 종료 후 개인별 점수, 처치 수, 생존 시간이 확인된다.
- 데스크톱과 모바일에서 주요 조작이 가능하다.
- `npm run typecheck`와 `npm run build`가 통과한다.

## 7. 주요 리스크

- 기존 문서와 일부 라벨의 한글 인코딩 깨짐
- 서버 메모리 기반 상태 관리로 인한 재시작 시 세션 유실
- 룸/전투/제작 로직이 단일 서버 파일에 집중되어 유지보수 난이도 상승
- 자동화 테스트 부족으로 밸런스 변경 시 회귀 확인이 어려움
